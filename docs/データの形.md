# 作品のデータの形（entries/e00001.json）

作品1件につき1ファイル。ファイル名は `id` と同じにします（例：`e00001.json`）。
CWカタログが読む形（[cw-catalog-tool の データ形式.md](https://github.com/seihayukimi-oss/cw-catalog-tool/blob/main/docs/開発者向け/データ形式.md)）に、管理用の項目を足したものです。
管理用の項目（下の表の「管理用」）は、公開するカタログ（`public/`）には出しません。

```json
{
  "id": "e00001",
  "state": "public",
  "type": "scenario",
  "name": "作品名",
  "author": "作者名",
  "version": "1.00",
  "updated": "2026-10-26",
  "format": "classic",
  "downloads": [
    { "label": "作者サイト", "url": "https://…/dl.html", "kind": "page", "status": "active" }
  ],
  "rating": "all",
  "content": [],
  "tags": ["短編"],
  "description": "紹介文",
  "intro": [{ "url": "https://…（紹介ページ）" }],
  "site": "https://…（作者様のサイト）",
  "checked": "readme",
  "claim": "proxy",
  "registered": "2026-10-26T12:00:00Z",
  "edit_key_hash": "（編集キーの SHA-256。キーそのものは保存しない）"
}
```

| キー | 中身 |
|---|---|
| `id` | `e` ＋ 5桁以上の数字 |
| `state` | `public`（公開）／`pending`（承認待ち）／`held`（一時保留中。CWカタログでは、いつもは表示しない）／`private`（非公開）／`removed`（登録解除）。`pending`・`private`・`removed` はカタログに出さない |
| `held_reason` | 一時保留の理由（任意） |
| `type` | `scenario`／`skin`／`material` |
| `name`・`author` | 作品名・作者名（必須） |
| `downloads` | 配布先（必須・1件以上）。`kind`：`page`（配布ページ）／`direct`（ファイルそのもの）／`list`（アップローダーなどのファイル一覧）。`status`：`active`（現役）／`mirror`（予備）／`old`（旧・移転済み）／`closed`（終了） |
| `rating` | 対象年齢：`all`／`r15`／`r18`。`r18` の作品は `index-r18.json` に入る |
| `content` | 注意ラベル：`gore`（グロ・残酷描写）／`horror`（ホラー）／`sexual`（性的な表現・R15相当）。`catalog.json` の `content_labels` で増やせる |
| `checked` | 登録した人が、どこで確かめたか：`readme`／`site`（作者様のサイト・配布ページ）／`author`（作者様本人から）／`other` |
| `derivative` | 改変版のとき：`{ "of": "もとの作品", "basis": "改変してよいと分かるもの" }` |
| `claim` | `author`（作者様本人・サイト認証済み）／`proxy`（代理登録） |
| `registered`・`changed` | 管理用：登録・変更の日時 |
| `edit_key_hash` | 管理用：編集キーの SHA-256（キーそのものは保存しない）。同じ作者様の作品は、同じ作者本人の編集キーを共有できる（まとめて認証・作者本人の編集キーでの登録） |
| `verified` | 管理用：本人の登録にした記録 `{ "at": "…", "where": "（コードが見つかったページ）" }`。作者本人の編集キーで登録したときは `{ "at": "…", "via": "author_key", "from": "e00001" }`（キーを持っていた作品） |
| `same_name` | 管理用：同じ作者名で、別のサイトで認証した作者本人の作品があったとき `{ "others": [{ "id": "e00012", "site": "example.com/abc" }], "at": "…" }`。止めはしないで、管理ページと Discord で知らせる（同じ名前の別の作者様か、なりすましでないか確かめる） |
| `approved` | 管理用：管理ページで承認した日時 `{ "at": "…" }` |
| `report_hold` | 管理用：通報が集まって自動で一時保留にしたとき `{ "reason": "r18", "count": 5, "at": "…" }`。公開に戻すと消える |

公開するカタログでは、作者本人の作品に `verified_site`（認証したサイトの短い形：ホスト名＋最初の部分。例 `seesaawiki.jp/abc`）を付けます。作者本人の編集キーで登録した作品は、キーを持っていた作品のサイトです。同じ名前の別の作者様を見分けるのに使います。

そのほか `version`・`updated`・`format`・`wsn_version`・`compat`・`convert`・`tags`・`description`・`intro`・`site`・`readme`・`file`・`level`・`origin` は、CWカタログのデータ形式と同じです。
`compat` がないときや `unknown` のときは、カタログを作るときに `format` から決めます（クラシック：1.50・Next・Py とも「動くはず」、Next仕様：Next だけ「動くはず」、Py仕様（WSN）：Py だけ「動くはず」で、ほかは「動かない」。形式が「なし」のときは「不明」のまま）。

## よく使うタグ（catalog.json の tag_presets）

登録ページのタグの欄の下に並ぶボタンです。管理ページの「ラベル」タブの「よく使うタグ」で直せます（60個まで。1つのタグに「、」や空白は入れられません）。公開するカタログ（`index.json`）にも `tag_presets` として出し、登録ページはそれを読みます。

## 注意

- このリポジトリは公開されています。**作品のファイルの中身・メールアドレス・IPアドレスなど、公開してはいけないものは入れません**（通報の数やIPは、受付の側に、元に戻せない形で一時的に置きます）
- ファイルを消しても、GitHub の履歴には残ります
